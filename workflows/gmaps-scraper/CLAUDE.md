# gmaps-scraper

Google Maps ICP scraper. Given a business vertical (e.g., "salons", "gyms", "dental clinics") and one or more locations, scrape public Google Maps listings with Playwright, apply ICP filters (rating band, review volume, profile completeness), and emit JSON + a browsable HTML report.

**Working directory:** this workflow's root (the directory containing `scraper.js`, `report.js`, `package.json`). All paths below are relative to it.

## Job to be done

Find target businesses matching an Ideal Customer Profile in a set of Indian locations, with enough data per listing to prioritize outreach — rating, review count, whether they respond to reviews, whether their profile is complete.

## How to invoke

One-time setup:

```bash
npm install
npx playwright install chromium
```

Scrape:

```bash
# Single query
node scraper.js "salons in Chittaranjan Park New Delhi"

# Batch across the 5 configured locations (edit TARGET_LOCATIONS in scraper.js to change)
node scraper.js --batch "salons" --incomplete-only --delay-multiplier 1.5
```

Render the latest batch as an interactive HTML report:

```bash
node report.js
```

Full CLI flag reference and target locations are in `README.md`.

## Input / Output contract

**Input:** CLI invocation with a query string and/or `--batch <vertical>`, optional ICP flags (`--min-rating`, `--max-rating`, `--max-reviews`, `--incomplete-only`, `--delay-multiplier`).

**Output** (all in `output/`):

| File | Content |
|---|---|
| `all_results_{timestamp}.json` | Every scraped business |
| `icp_filtered_{timestamp}.json` | Businesses matching ICP filters only |
| `report_all_results_{timestamp}.html` | Interactive, sortable, filterable HTML table generated by `report.js` from the latest JSON |
| `partial_{timestamp}.json` | Written on crash/block; contains whatever was scraped before the failure |

Each business record: `business_name`, `category`, `rating`, `review_count`, `phone`, `website`, `address`, `location_area`, `google_maps_url`, `has_hours`, `photo_count`, `latest_review_has_reply`, `meets_icp`.

## Notes for agents

- **Respect Google's rate limits.** The scraper already has stealth + random delays + periodic pauses. If you get blocked, bump `--delay-multiplier` before retrying; don't parallelize.
- **Partial results are not failures.** If the scraper exits early with a `partial_*.json`, that data is still useful — treat it as a successful-but-incomplete run.
- **Reports read the latest `all_results_*.json`.** `report.js` auto-picks the newest file in `output/`; regenerate after each scrape.
- See `README.md` for the full CLI reference, anti-detection details, and how to extend target locations.
